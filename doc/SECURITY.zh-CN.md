## 报告漏洞

如果你在本项目中发现安全漏洞，请负责任地报告。

### 如何报告

**不要**为安全漏洞公开提交 Issue。


报告中请包含以下信息：
- 漏洞描述
- 复现问题的步骤
- 漏洞的潜在影响
- 任何建议的修复或缓解措施（如果可用）

### 响应时间表

我们将在 48 小时内确认收到您的报告，并在 7 天内提供详细回复，包括：
- 漏洞确认
- 修复的预期时间表
- 如需要，协调披露事宜

### 披露政策

一旦漏洞被修复，我们将：
1. 尽快发布安全更新
2. 发布详细的安全公告
3. 归功报告者（如果愿意）
4. 在 CHANGELOG 中更新安全修复

## 安全最佳实践

### 对于用户

- 保持依赖项更新
- 使用强 JWT 密钥
- 在生产环境中启用 HTTPS
- 定期审查访问控制
- 监控日志中的可疑活动

### 对于部署

- 永远不要在代码中暴露存储凭据
- 使用环境变量存储敏感配置
- 在 API 端点实施速率限制
- 保持 GraphicsMagick 更新
- 使用安全的存储配置

### 配置安全

- 立即更改默认凭据
- 为存储服务使用强密码
- 限制对存储端点的网络访问
- 为 Admin UI 启用身份验证
- 使用安全的 JWT 令牌过期设置

## 依赖安全

本项目使用以下安全实践：
- 定期更新依赖项
- CI/CD 中的漏洞扫描
- 签名发布
- 下载验证校验和
